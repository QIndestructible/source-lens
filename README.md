# 信源体检器 · Source Lens

搜回来 20 条结果，可能只有 17 个人在说话。

这个小工具会去[元宝搜索](https://cloud.tencent.com/document/api/1806/121811)拉一批结果，把转载和同源包装去掉，然后回答一个问题：**这批结果里到底有几个独立信源。**

它是给 RAG 用的：模型看到三条链接说同一件事，就会写「多方已证实」。可如果这三条是同一篇通稿的三个域名版本，它拿到的是 1 票。把这件事算清楚，再喂给模型，比多塞十条结果有用。

## 快速开始

需要 Python 3.9+，没有任何第三方依赖。

```bash
git clone https://github.com/QIndestructible/source-lens.git
cd source-lens
copy config.example.py config.py      # macOS/Linux: cp config.example.py config.py
# 打开 config.py，填入你的 WSA_API_KEY

python app.py
```

浏览器会自动打开 `http://127.0.0.1:8765`，输入问题，回车。

Windows 用户也可以直接双击 `start.bat`——它只是帮你找到 Python 再执行上面那条命令，不是必须的。

## 界面能看到什么

- **四个数字**：结果条数、独立信源、独立信源密度、疑似重复条数
- **同源转载**：哪几条是同一篇，覆盖了几个域名
- **信源结构提示**：一段可以直接拼进 RAG prompt 的话，一键复制
- **结果明细**：站点、日期、相关度；同一篇的排在一起并标「同源 ×N」

## 怎么判断「同一篇」

1. 标题去掉站点后缀（`_新浪财经`、`- 网易`），压掉标点和空格；
2. 正文删标点，切成连续的 3 个字一组，比较两篇的 Jaccard 相似度；
3. 相似度 ≥ `0.55`，或者标题一致，就并成一堆（并查集）；
4. 合并后每一堆算一个独立信源。

阈值 0.55 是调出来的：再高，改过导语的转载会漏；再低，同一事件的两篇不同报道会被误并。

## 参数

| 参数 | 说明 | 建议 |
| --- | --- | --- |
| 条数 | 10 / 20 / 30 / 40 / 50 | 20 够用，50 更全 |
| 时效 | `dN` / `mN` / `yN` / 单日 / 区间 | 追新事件 `d7`，一般调研 `m1` |
| 模式 | 0 公开网页 / 1 权威垂直 / 2 混合 | 2，一手公告常在垂直信源里 |

## 三个限制

- 只测「证据独不独立」，**不测内容对不对**。九家转发一条错消息，密度照样高。
- 改写过度的转载会漏判，密度虚高；同一事件的两篇不同报道可能被误并，密度虚低。
- 独立域名不等于独立生产者。一个编辑部开三个号，这套算法看不出来。

## 目录

```
app.py            本地 HTTP 服务 + /api/search
cli.py            命令行出报告（不开浏览器）
core.py           检索、判重、算指标
ui.html           界面
report_stats.py   用 data/evidence 复算全部指标
data/evidence/    20 个 JSON，400 条真实检索结果
config.example.py 配置模板（复制成 config.py 再填 key）
start.bat         Windows 一键启动（可选）
```

## 复现这些数字

仓库里带着那 400 条原始结果，不用重新调接口：

```bash
python selftest.py        # 12 项离线自检：判重、分层、日期解析
python report_stats.py
```

输出应该是 `400 条 / 332 信源 / 密度 83.0% / 重复 68 条 / 前三平台 23.2%`。
改了判重阈值或算法，跑一遍就能看到数字怎么变。

单题出报告：

```bash
python cli.py "算力券 政策 最新进展" --cnt 20 --out report.md
```
